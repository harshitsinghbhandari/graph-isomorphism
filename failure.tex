\section{Purpose}

This appendix records what the current relaxation-and-rounding pipeline does
not solve yet.
It is intentionally conservative: only the active source code is treated as
implemented.

\section{Failure Mode 1: The Score Is Not a Decision Rule}

The code reports
\begin{equation}
    I=\exp(-\lambda Z^*),
\end{equation}
but $I$ has no universal correctness threshold.

A high score means the relaxed objective found a low-cost soft correspondence.
It does not prove that a permutation exists.
A low score suggests mismatch under the current objective, but it is also not
a formal proof of non-isomorphism.

The only positive certificate in the current method is the exact residual check
\begin{equation}
    AP^*=P^*B.
\end{equation}

\section{Failure Mode 2: Diffuse Optima}

The relaxation can return a fractional matrix even when the graphs are
isomorphic.
This is common when the graph has automorphisms or when the objective has many
equivalent near-minimizers.

A typical extreme case is the uniform matrix
\begin{equation}
    X_{ij}=\frac{1}{n}.
\end{equation}
Such a matrix can be excellent for the relaxed objective but useless as a
permutation witness.

This is why rounding is not optional.

\section{Failure Mode 3: Weak Degree Features}

The current cost matrix uses only degree and one-hop neighbor-degree summaries.
These features are cheap, but they are not complete graph invariants.

They are weak on:
\begin{itemize}[leftmargin=*]
    \item regular graphs;
    \item strongly regular graphs;
    \item highly symmetric graphs;
    \item graphs where many vertices share identical local profiles.
\end{itemize}

On such cases, $C$ may become nearly uniform and the solver falls back mostly
to the adjacency commutator.

\section{Failure Mode 4: Rounding Can Miss a Witness}

The active rounding method uses SVD embeddings of $X^*$ and randomized
hyperplane signatures.
It is a heuristic extraction step.

If it returns a permutation with nonzero residual, the correct conclusion is
\begin{quote}
not certified by this run,
\end{quote}
not
\begin{quote}
proved non-isomorphic.
\end{quote}

This distinction must be kept clear in the presentation.

\section{Failure Mode 5: Random Non-Isomorphic Labels}

The generator for random pairs samples two graphs independently.
For moderate and large $n$ this is almost surely non-isomorphic, but for small
$n$ accidental isomorphism can happen.

Therefore benchmark accuracy claims should use VF2, nauty, or bliss as the
ground-truth label, not the generator name alone.

\section{Failure Mode 6: Scaling}

The model has $n^2$ continuous variables and $2n$ equality constraints.
The current Python construction of the adjacency residual builds nested
expressions over $(p,q,k)$, giving an $O(n^3)$ expression-building bottleneck.

This is the practical reason the solver becomes expensive near 100 nodes,
while VF2, nauty, and bliss remain extremely fast on the tested random dense
instances.

\section{Priority Fixes}

The most useful next improvements are:
\begin{enumerate}[leftmargin=*]
    \item add stronger node compatibility features, especially WL colors;
    \item compare Hungarian and hyperplane rounding on the same saved $X^*$;
    \item normalize both objective terms across graph sizes;
    \item add hard benchmark families beyond dense random graphs;
    \item reduce model-building overhead for the adjacency residual.
\end{enumerate}
